# СМЕТА-ГАЗ 2.5 — обновлённый проект

Рабочая сборка исходного Python/PyQt6-приложения из 20 предоставленных модулей. Добавлены общая база клиентов, индексированный поиск, постраничные реестры, настраиваемый экспорт и проверяемые полные резервные копии. Это исходный проект, не Windows EXE.

Из сметы убраны начисления на работы (они входят в цену работ справочника); «Расшифровка работ» и «Маржа» объединены в одно окно с экспортом по шаблону; смета создаётся под клиента из базы, юрлицо или клиента из карточки договора, по умолчанию без договора, договор привязывается позже; переработаны шаблоны и теги (русские теги, редактор, проверка шаблона). **Справочник ГСН** стал полностью независимым от ГСВ — со своим реестром сертификатов. **[Инструкция](docs/ESTIMATES_GUIDE_RU.md)**.

## Запуск

Нужен Python 3.11 или 3.12 (проверено на 3.12). Для установки зависимостей нужен интернет.

Windows: распакуйте архив и запустите `start_windows.bat`. Либо выполните в папке проекта:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Для Linux нужны системные библиотеки Qt/X11 или Wayland. Проверка GUI в этой сборке выполнена в Linux с `QT_QPA_PLATFORM=offscreen`. Windows, печать на физическом принтере и реальные пользовательские шаблоны здесь не проверялись. SQLite должен поддерживать FTS5 (обычно включён в официальных сборках Python).

## Перенос существующих данных

1. Закройте старую программу и сохраните копию всей её папки.
2. Скопируйте `smetagaz.db`, папки вложений, `projects`, `templates`, `attachments`, `certificates_storage` в отдельную папку данных. Если старая база была открыта, копировать только `.db` нельзя: сначала закройте программу. Самый надёжный вариант — копия всей папки после закрытия.
3. Запустите новую программу с этой копией:

```powershell
.venv\Scripts\python.exe run.py --data-dir "D:\SmetaGazData"
```

Перед первым изменением схемы создаётся снимок старой базы в `backups/before_upgrade_*`. Старые дополнительные колонки сохраняются. Без `--data-dir` используется папка `.smetagaz` в домашней папке пользователя. Базы и документы больше не зависят от текущей папки запуска.

Если старые вложения указаны абсолютными путями, оставьте исходные файлы доступными до создания полной резервной копии. Она перепишет пути в своём снимке для переноса. Оригинальная база при этом не меняется.

## Клиенты

Раздел «Клиенты» использует отдельную `clients.db`. Связи с модулями хранятся через `client_id`.

- Существующие клиенты извлекаются из смет и ГСВ. Автоматическое объединение при миграции — только при совпадении имени и непустого телефона; однофамильцы без телефона не объединяются.
- В договоре и карточке ГСВ сначала вводятся данные клиента. При сохранении автоматически создаётся запись в «Клиенты». Вторичная кнопка «Заполнить из «Клиенты»…» позволяет выбрать существующего клиента даже до первого сохранения договора. Повторное сохранение той же карточки обновляет связанного клиента. В смете сохранён выбор клиента из базы.
- В «Все реестры» можно связать с клиентом также ГСН, задачу, событие и запись списания.
- Изменение имени/телефона в общей карточке синхронизируется со связанными сметами, договорами и ГСВ. Экспорт получает актуальные общие сведения по идентификатору.
- Старые текстовые поля имени/телефона сохранены как совместимый кэш. Адрес объекта и паспортные реквизиты ранее оформленного договора не переписываются массово: выбор клиента заполняет реквизиты карточки, затем её нужно сохранить.
- Новая смета, введённая вручную без выбора существующего клиента, может создать отдельного клиента. Для повторных заказчиков используйте выбор из базы; массовое слияние дублей с проверкой конфликтов не реализовано.

Материалы и сварщики сами по себе не являются заказами клиента и не имеют искусственной привязки к нему.

## Новое в 2.1: ГСВ и сварочные работы

Панель перехода между страницами теперь занимает 44 пикселя; основное место отдано таблице.

### Оборудование и трубопроводы

В карточке договора на монтаж и карточке ГСВ есть отдельные вкладки оборудования, трубопроводов и исполнительных документов. Оборудование выбирается из списка: Счетчик, Сигнализатор, Котел, Колонка, ПГ, Регулятор. Тип/модель и номер сертификата или паспорта вводятся вручную.

Откройте «Справочники ГСВ», создайте вид трубы и укажите сертификат: выберите существующую запись либо путь к файлу. Затем выберите трубу в договоре и сохраните карточку. Сертификат автоматически появится в исполнительных документах объекта. Обновление сертификата в справочнике отражается в связанных объектах. Неиспользуемые виды можно отключить, сохранив старые связи.

### Четыре вкладки сварочного модуля

1. **График производства работ.** В версии 2.2 это журнал: дата, место, работа, сварщик, примечание. Введите данные произвольно. Выбор договора, работы из сметы или прежней записи — вторичный вариант. Каждая сохранённая строка отображается в общем календаре. Фильтры периода находятся над таблицей.
2. **Сварщики.** Карточка содержит ФИО, дату рождения, телефон, аттестацию, вид сварки, клеймо, разряд и срок аттестации. Сохраните нового сварщика, затем добавляйте его документы во второй вкладке карточки.
3. **Аттестация.** Общий реестр документов других лиц, связанных со сваркой.
4. **Договоры и акты.** Реестр договоров, протоколов и актов механических испытаний с реквизитами и путями к файлам.

Документы сварочного модуля хранятся **только как ссылки на файлы компьютера**. Их можно зарегистрировать сразу несколько. Удаление записи не удаляет исходный файл. Если файл перемещён, исправьте путь в карточке документа; недоступный путь отмечается в интерфейсе.

В сохранённой карточке объекта откройте «Исполнительные документы», нажмите добавление из реестра и выберите нужные документы. Один документ можно связать с несколькими объектами. Кнопка «Связанные объекты» в реестре показывает обратные связи. Автоматические сертификаты труб и ручные ссылки на сварочные документы отображаются вместе. Экспорт включает перечень этих документов; он не превращает все внешние файлы в один объединённый PDF.

Снимки интерфейса находятся в `docs/v2.1/` и `docs/v2.2/`. При обновлении существующей базы сохраняются прежние данные; недостающие реквизиты клиента переносятся в общую базу из старых карточек. Совпадение ФИО само по себе не объединяет разных клиентов — для повторного заказа выбирайте существующего.

## Поиск и большие объёмы

`Ctrl+K` открывает поиск по клиентам, сметам, договорам, ГСВ/ГСН, материалам, сертификатам, задачам, календарю, названиям вложений, сварщикам, сварочным документам/работам, трубопроводам и списаниям. Поддерживаются кириллица без учёта регистра, несколько слов и начало слова. Результаты выдаются страницами по 100, двойной щелчок открывает запись.

Поиск индексируется автоматически в транзакции изменения записи. Поиск по произвольному фрагменту внутри слова, OCR и содержимому DOCX/PDF/сканов не реализованы. Формат телефона влияет на разбиение на слова: для `+43 555` ищите `555` или `43 555`.

Основные реестры показывают по 200 записей, универсальный обзор — по 100. Вкладки создаются при первом открытии. Копирование нескольких выбранных вложений, новые экспорты и резервные копии работают в фоне. Импорт вложений читает по 1 МиБ, поддерживает отмену, уникальные имена и отчёт по ошибкам; исходные файлы не удаляются.

Редактор одной сметы, старый импорт Excel, статистика и некоторые старые выпадающие списки всё ещё могут загружать большой набор целиком. Для крупных реестров используйте «Все реестры». Миллионы позиций в одной смете и сотни гигабайт вложений не тестировались.

## Word, Excel, PDF

В карточках сметы/договора нажмите «Настроить Word / Excel / PDF», либо выберите запись в «Все реестры» и нажмите «Экспорт».

Для каждой записи отдельно сохраняются: заголовок, организация, список полей, шрифт Word/Excel, размер шрифта, поля Word/PDF, ориентация и разрешение включить телефон/адрес/паспорт. Перед каждым экспортом можно изменить параметры и имя выходного файла. Это профиль записи, общий для трёх форматов, а не отдельная база профилей каждого выходного пути.

PDF использует встроенный DejaVu Sans с кириллицей. Word/Excel зависят от доступности выбранного шрифта на компьютере. Смета включает позиции и оплаты; договор — оборудование, трубопроводы и перечень исполнительных документов. Новые документы являются структурированными выгрузками, а не гарантированными отраслевыми/юридическими бланками. Существующие специализированные PDF и шаблон договора ГСВ сохранены.

Excel получает строки как текст, включая значения, начинающиеся с `=`; это предотвращает выполнение подставленных формул. Запись новых экспортов — во временный файл с последующей заменой готового результата.

## Резервные копии

Автоматическая полная ZIP-копия — раз в час во время работы программы; проверка — раз в минуту, хранение последних 24 автоматических копий. Непрерывного фонового сервиса при закрытой программе нет. Копии находятся рядом с данными в `backups`.

Включены: обе базы, настройки/профили, связанные вложения и сертификаты, управляемые папки проектов и шаблонов. Внешние доступные вложения и сертификаты тоже копируются. Документы сварочного модуля — исключение: сохраняются только записи и исходные пути, сами файлы не копируются; список ссылок есть в манифесте. Их оригиналы нужно резервировать отдельно. Список файлов и SHA-256 находятся в `manifest.json`. Отсутствующие исходные файлы явно перечисляются; содержимое недоступного файла восстановить невозможно.

В настройках можно создать обычную `.zip` или зашифрованную `.sgb` копию. Шифрование — AES-256-GCM с ключом из пароля через scrypt. Пароль копии необходимо сохранить отдельно: механизма восстановления пароля нет. Автоматические ZIP-копии не зашифрованы.

Восстановление проверяет пути, состав архива, контрольные суммы и SQLite `integrity_check`, затем создаёт **новую папку**. Открытая база не подменяется. Для переключения запустите `run.py --data-dir "путь_к_восстановленной_папке"`. После проверки ненужные копии можно удалить вручную.

Не изменяйте исходные внешние документы другими программами во время копирования. Две базы снимаются последовательно под общей блокировкой приложения; внешние процессы, обходящие приложение, в эту гарантию не входят.

## Защита

Можно установить пароль входа в настройках. Хранится соль и scrypt-хэш, ограничены повторные неудачные попытки. Второй экземпляр приложения не открывает ту же папку данных. В Linux новые папки/файлы получают ограниченные права там, где это поддерживает файловая система.

**Пароль интерфейса не шифрует рабочие SQLite-базы и не заменяет права ОС.** Для защиты украденного/скопированного диска используйте шифрование диска и отдельную учётную запись ОС. Нет многопользовательских ролей, защиты от администратора компьютера, полноценного аудита изменений и сетевого сервера.
