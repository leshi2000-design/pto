# Аудит и изменения — версия 2.4

Проверены предоставленные 20 модулей. Сборка сохраняет существующий PyQt6-интерфейс и редакторы, дополняя их общими сервисами. Формулировка «исправлены все недостатки» была бы недостоверной: без реальной базы, документов, требований к отраслевым формам и испытаний на рабочем компьютере это подтвердить нельзя.

## Почему выбрана такая архитектура

Для локального рабочего места сохранены SQLite и PyQt6: миграция существующих данных и редакторов обходится без переписывания приложения. Для базы клиентов используется ATTACH к той же транзакции. Выбран журнал DELETE и synchronous FULL: SQLite отдельно предупреждает, что при WAL транзакция нескольких файлов не гарантирует общую атомарность при аварии компьютера. [Документация ATTACH](https://www.sqlite.org/lang_attach.html).

Для снимков применён SQLite Backup API вместо копирования активного `.db`; он предназначен для согласованных снимков базы. Копирование документов выполняется после снятия блокировки приложения. [Документация Backup API](https://www.sqlite.org/backup.html).

Два разных требования разделены: пароль входа ограничивает использование интерфейса, а шифрование копии защищает её содержимое. Рабочие БД остаются незашифрованными. Полное шифрование диска/защищённая учётная запись нужны отдельно; это нельзя достоверно заменить окном с паролем.

## Что ещё необходимо для промышленной эксплуатации

1. **Приёмка на копии реальной базы.** Проверить числа/округления, нестандартные колонки старых таблиц, отсутствующие вложения, даты и ваши шаблоны. Настоящая база и сами рабочие документы не были приложены.
2. **Специализированные модули.** Реестр ГСН не выполняет гидравлические расчёты; реестр сварщиков не проверяет НАКС; списания в 2.2 ведут количественные остатки, но не стоимость партий и бухгалтерские проводки. Точные бланки белорусских С-29 и С-1 не подтверждены; встроены явно обозначенные рабочие проекты.
3. **Сервер для нескольких сотрудников.** При одновременной работе нескольких компьютеров нужен серверный API и клиент-серверная СУБД с ролями. Не следует превращать текущие файлы SQLite в общую сетевую базу. Это соответствует ограничениям модели использования SQLite. [Рекомендации SQLite](https://www.sqlite.org/whentouse.html).
4. **Поиск внутри документов.** Отдельная очередь извлечения текста и OCR, хранение контрольных сумм/статуса обработки, ограничения размера и повторная индексация только изменившихся файлов. Сейчас поиск — по данным и именам файлов.
5. **Рабочие базы с шифрованием и аудитом.** Если требуется защита именно файла БД, нужен отдельный проект интеграции шифрованного SQLite с управлением ключами, резервным доступом и восстановлением. Для нескольких пользователей — роли и журнал событий на сервере.
6. **Оставшиеся тяжёлые старые операции.** Чтение больших Excel, статистику, редактор огромной сметы и некоторые селекторы следует перевести на QAbstractTableModel/потоковую обработку. Новая версия ускоряет реестры и новые фоновые операции, но не гарантирует отсутствие задержек на любом старом сценарии.
7. **Копии вне компьютера.** Настроить отдельную копию на другом носителе/сервере и периодически проверять восстановление. Автокопии рядом с базой не спасают при потере всего диска.

Гарантировать отсутствие всех ошибок по статическому анализу и синтетическим тестам нельзя. Это проверенная доработка исходного проекта с обозначенной границей функциональности, а не сертификация безопасности и отраслевых расчётов.


## Версия 2.3 — ГСН и шаблоны исполнительной документации

- Схема 5: карточки ГСН, общие технические поля и материалы, шаблоны модуля и индивидуальные исключения, журнал созданных документов. Перед обновлением сохраняется снимок баз. Индекс поиска ГСН теперь включает номер договора, клиента и телефон.
- Заполнение DOCX/XLSX без пересоздания всего документа сторонними редакторами: меняются OOXML-тексты; поддержаны разделённые Word-теги, таблицы/колонтитулы, числовые количества Excel, исходные формулы и оформление. Неверные/неполные теги блокируют комплект.
- Сертификаты материала по умолчанию и отдельные привязки в договоре. Снимок использованных значений остаётся в журнале; сгенерированные файлы не обновляются задним числом.
- Фоновое создание с предварительной проверкой, временной папкой и очисткой созданных результатов при обычной ошибке. Аварийное отключение питания между записью файлов и журнала может оставить незарегистрированные файлы: содержимое доступно в папке; пользовательские файлы не удаляются.
- Папки договоров, шаблоны и созданные документы включены в резервную копию. Запрещено размещать копию внутри резервируемой папки, чтобы избежать рекурсивного копирования.
- Дополнительно проверено обновление реальной сборки 2.2 из ранее выданного архива: записи ГСН сохранены, создан снимок до миграции, повторная инициализация не дублирует шаблоны.
- Проверено 32 автотеста и четыре сценария GUI: основной интерфейс, ГСВ/сварка, списания, новый ГСН. Сохранение/повторное открытие ГСН, автоматическое создание клиента, сертификаты, фоновая генерация и фильтры проверены через реальные виджеты Qt.
- Ограничения: нет предоставленных пользовательских бланков; фактическая печать и Windows не проверены. Новые заполненные шаблоны создаются DOCX/XLSX; PDF через Word/Excel. Настоящие данные сварочного аппарата добавляются готовым файлом. Результаты на реальной базе и реальных документах требуют проверки пользователя.


## Версия 2.4 — правки по интерфейсу и файлу пользователя

Схема 6. Ошибочное применение актов ГСН к ГСВ исправлено; старые конфигурации сохраняются в архивном разделе таблицы, документы не удаляются. Единая встроенная тема больше не зависит от необязательного qdarktheme. Навигация со значками, прокруткой и заголовками; уплотнены таблицы и панель смет.

Шаблоны отчётов хранятся по типу документа; выбор запоминается для записи. Добавлены повторяющиеся строки Word и Excel с сохранением структуры OOXML, числовые значения, полные позиции сметы и подпись составителя. Для повторяемых XLSX запрещены формулы и сложные объекты, которые нельзя безопасно сдвинуть этим механизмом; пользователю предлагаются готовые теги итогов. Для неповторяемых шаблонов формулы сохраняются. Это ограничение явно показано при проверке и описано в инструкции.

Исполнительная документация хранится отдельными комплектами. Автоматические сертификаты, дополнительные ручные сертификаты и документы сварки собираются в подпапку договора. Сигнатура включает шаблон и реально используемые значения. Неизменившиеся результаты не переписываются; ручные изменения защищены при переформировании. Публикация комплекта откатывает обычные ошибки записи. Аварийное отключение питания во время нескольких замен файлов не является полностью транзакционным; сохраняйте резервные копии.

Оплаты используют одну таблицу payments: связанные договор и смета видят один платёж. Старый положительный остаток учтённой оплаты сохранён отдельно без выдумывания дат платежей. Отчёт группирует по реальным датам и разделам. Теги задач нормализованы связями; названия статусов и теги доступны поиску.

Резервирование сохраняет папки и вложенные пути согласованно — после восстановления можно продолжить переформирование ИД. Проверена миграция из фактически выданного архива 2.3: сохранены ГСН, история файлов, старые шаблоны ГСВ, суммы ранее учтённой оплаты; повторная инициализация не дублирует данные.

46 автотестов; шесть сценариев GUI. Физическая печать, Windows и реальные бланки пользователя не проверены. Тесты не подтверждают отсутствие всех возможных дефектов. Пользовательский PDF из DOCX/XLSX пока требует Word/Excel; стандартный PDF-экспорт сохранён.
