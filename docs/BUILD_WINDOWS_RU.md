# Сборка программы для Windows

## Как собрать
1. Установите **Python 3.11 или 3.12 (64-bit)** с python.org (при установке отметьте «Add python.exe to PATH»; Python 3.14 и новее для сборки не подходит — для pandas и других библиотек нет готовых пакетов, и pip пытается собирать их из исходников, требуя Visual Studio).
2. Распакуйте архив с программой и запустите **`build_windows.bat`** двойным щелчком (не `pyinstaller` вручную). Скрипт сам создаёт папку `.venv`, ставит все библиотеки из `requirements.txt`, собирает программу и проверяет результат. По умолчанию собирается **только программа** (для работы на одном компьютере). Чтобы добавить ещё и ПТО Сервер для сети, запустите `build_windows.bat server`.
3. Готово: `dist\ПТО\PTO.exe` (программа; с параметром `server` ещё и `PTO_Server.exe`). Если установлен Inno Setup, ещё и установщик `dist\PTO_Setup.exe`. Запускать нужно **из папки `dist\ПТО`**, а не отдельный exe, скопированный в другое место: рядом должны лежать папка `_internal` и остальные файлы.

## Что показывает скрипт
- Строка `Python 3.12.x | PyQt6 6.x.x` — подтверждение, что PyQt6 установлен в `.venv`.
- В конце — результат самопроверки программы (`PTO.exe --selftest`) (`ВСЁ В ПОРЯДКЕ` или `FAIL <модуль>`).

## Важно для версий 4.5.1–4.5.3
В этих версиях файл `requirements.txt` по моей ошибке оказался пустым, поэтому PyQt6 и другие библиотеки не устанавливались, и программа после сборки не запускалась («No module named 'PyQt6'»). Исправлено в 4.5.4: файл восстановлен, есть автотест, который проверяет, что в нём перечислены все нужные библиотеки, а `build_windows.bat` отказывается работать с пустым файлом. Если собираете из старой папки — удалите `.venv`, `build`, `dist` и пользуйтесь 4.5.4.

## Если программа пишет «No module named 'PyQt6'»
Значит, PyQt6 не попал в сборку. Почти всегда причина в том, что PyInstaller был запущен Python-ом, где PyQt6 не установлен (например, из другой установки Python или командой `pyinstaller ...` вручную).
1. Удалите папки `build`, `dist` и `.venv` рядом с программой.
2. Запустите `build_windows.bat` заново. Если на шаге pip что-то красное — прочитайте сообщение (нет интернета, не тот Python, антивирус блокирует).
3. Если строка `Python ... | PyQt6 ...` не появилась, скрипт остановится сам с объяснением; ничего «молча сломанного» больше не собирается.
4. Проверьте версию: `.venv\Scripts\python.exe --version` должна быть 3.11 или 3.12.

Если ошибка осталась, пришлите: (а) весь вывод `build_windows.bat` начиная со строки `Python ...`, (б) файл `dist\ПТО\selftest.txt`, (в) полный текст ошибки при запуске.

## Запуск из исходников (без сборки)
```
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py            (сервер: run_server.py)
```

## Если собранная программа не запускается (с 4.8.1)
У PTO.exe нет консоли, поэтому раньше ошибка запуска была не видна. Теперь:
* при любой ошибке старта программа показывает окно «ПТО — ошибка запуска» и сохраняет **`startup_error.txt`** — рядом с `PTO.exe` и в папке данных (`C:\Users\<имя>\.smetagaz\`). Пришлите этот файл;
* `build_windows.bat` после сборки запускает `PTO.exe --selftest` — самопроверка теперь не только импортирует библиотеки, но и создаёт пустую базу во временной папке, выполняет все миграции и открывает **каждый раздел меню**; результат — `dist\ПТО\selftest.txt` (на экране выводится в конце сборки). Данные пользователя самопроверка не трогает;
* журнал работы — `app.log` в папке данных.

## Обновление без пересборки (с 4.9.5)
После установки версии 4.9.5 (сборка `build_windows.bat` — один раз) следующие версии ставятся из программы: **Справка → «Обновить программу из ZIP…»**. Пересборка нужна, только если обновлению нужны новые библиотеки (программа предупредит). Подробности — `docs\UPDATE_4_9_5_RU.md`.

## Ошибка «Could not find vswhere.exe» / «meson setup» при установке pandas (исправлено в 4.9.6)
Причина — слишком новый Python (3.14 и выше): для него нет готового пакета pandas, и pip запускает сборку из исходников, которой нужен Visual Studio. `build_windows.bat` теперь:
* сам выбирает Python **3.12 → 3.11 → 3.13 → 3.10** (через `py -3.12` и т. д.), а окружение `.venv`, созданное неподходящим Python, **пересоздаёт**;
* ставит библиотеки только готовыми пакетами (`--only-binary`), чтобы не доходило до сборки из исходников;
* если подходящего Python нет (например, стоит только 3.14) — объясняет это и **предлагает скачать и установить Python 3.12 автоматически** (ответ `Y`): с python.org, только для вашего пользователя, без прав администратора, ~25 МБ, нужен интернет; установленный 3.14 остаётся, `winget` не нужен. Если автоустановка не удалась — подскажет установить Python 3.12 вручную (python.org → Windows installer 64-bit → «Add python.exe to PATH») и запустить файл снова.
Если сборка уже упала с такой ошибкой: установите Python 3.12 (64-bit), удалите папку `.venv` рядом с `build_windows.bat` и запустите файл снова.
