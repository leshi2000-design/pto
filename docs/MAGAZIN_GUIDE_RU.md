# Магазин — первая рабочая версия

Отдельное настольное приложение на Python/PyQt6 для учёта товаров, предложений поставщиков и документов. Его база `shop.db` независима от баз СМЕТА-ГАЗ. Исходники находятся в `shop/`, точка запуска — `run_shop.py`.

## Запуск

Python 3.12, зависимости из существующего `requirements-tested.txt`:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-tested.txt
.venv/bin/python run_shop.py
```

В Windows используйте `start_shop_windows.bat` (нужен установленный Python 3.12). Windows EXE пока не собирался и запуск на Windows не проверен.

По умолчанию данные находятся в `.magazin` в домашней папке. Для другой папки:

```bash
.venv/bin/python run_shop.py --data-dir /путь/к/данным
```

В облачной среде домашняя папка доступна только для чтения, поэтому используйте:

```bash
export XDG_CACHE_HOME=/workspace/.cache
export QT_QPA_PLATFORM=offscreen
.venv/bin/python run_shop.py --data-dir /workspace/pto/.smetagaz/magazin
```

`offscreen` позволяет проверять приложение без монитора. На обычном компьютере эта переменная не нужна. Два экземпляра не могут открыть одну папку данных.

## Порядок работы

1. Заполните реквизиты своей организации: наименование, УНП, адрес, банк, IBAN и контакты.
2. Добавьте товары с уникальными артикулами или импортируйте их из прайса. Добавьте поставщиков и покупателей в «Контрагенты»: физлицо или юрлицо.
3. В «Прайсы» импортируйте XLSX либо CSV в UTF-8. Первая строка — заголовки. Выберите поставщика, валюту и столбцы артикула, наименования, цены и единицы. Ошибка в строке останавливает весь импорт без частично добавленных товаров. Повторный импорт того же файла обновляет предложения. При совпадении артикула используется существующий товар; поэтому согласуйте артикула разных поставщиков до импорта.
4. Прайс не создаёт складских остатков. Создайте документ «Поступление», внесите дату и номер исходной накладной в поле «Основание», добавьте позиции и нажмите «Провести». Исходную накладную можно прикрепить файлом.
5. Создайте «Счёт», выберите покупателя и товары. Кнопка «Подставить цену из прайса» предлагает цены поставщиков в валюте документа; продажную цену можно изменить. Цены документа задаются **без НДС**, ставка НДС — отдельно на каждой строке, без автоматического выбора ставки. Если прайс содержит цену с НДС, пересчитайте её перед заполнением документа. По умолчанию ставка 0, а не автоматически назначенные 20%.
6. Проведите счёт и сформируйте его по шаблону. Счёт не списывает и не резервирует товар. «Накладная из счёта» переносит зафиксированные позиции, цены и реквизиты покупателя в черновик отгрузки. Одна накладная на один счёт; частичные отгрузки в этой версии не реализованы.
7. Проведение отгрузки списывает товар. Нехватка любой позиции отклоняет документ целиком. Повторное проведение запрещено. Отмена отгрузки возвращает остатки; поступление нельзя отменить, если его отмена сделает остаток отрицательным. Перед отменой создаётся копия.

Количество хранится точно до 3 знаков, цены — до 2, ставки НДС — до 2. Сумма строки и НДС округляются до копеек. Обновление справочника или прайса не меняет позиции и цены сохранённых документов. Проведённые документы не редактируются: ошибочный документ отменяют и создают новый. Реализован учёт общего количества; партии, себестоимость, несколько складов, платежи, возвраты и бухгалтерские проводки в эту версию не входят.

## Сайты и категории

В «Сайты поставщиков» добавьте поставщика, адрес сайта и полные адреса нужных категорий, каждый с новой строки. Категории должны находиться на том же сайте. Укажите валюту и название категории в справочнике.

Программа сначала читает структурированные данные JSON-LD Product, затем пробует HTML-разметку. Если сайт не распознан, задайте CSS-селекторы карточки, названия, цены, артикула и ссылок на товары/следующие страницы. Например: карточка `.product-card`, название `.product-title`, цена `.price`, ссылки `.product-card a, a.next`. Это примеры; реальные классы берутся из разметки нужного сайта.

Обход ограничен выбранными путями категорий, распознанными ссылками карточек товаров и явно указанными селекторами ссылок. По умолчанию — максимум 30 страниц за обновление, настраивается до 300. При достижении лимита показывается предупреждение: прочитана только часть каталога. Автоматический обход произвольного сайта без его настройки не гарантируется.

Обновление — кнопкой, при запуске и раз в час **пока программа открыта**. Сетевой запрос выполняется в фоновом потоке, цены сохраняются основным потоком. TLS-проверка включена. Ошибки отдельных страниц не обнуляют предыдущие цены. Товары, исчезнувшие с сайта, автоматически не удаляются. Время успешного обновления каждой цены видно в прайсах; результат последнего обхода записывается в `sources/last-update.json`.

Предложения сайта привязаны к поставщику и URL, автоматически обновляются при следующих обходах. Для новых товаров сайта создаются отдельные артикулы `WEB-…`, чтобы не объединять разные товары по похожему названию. Объединение таких карточек с существующими артикулами в интерфейсе пока не реализовано.

Сайты с JavaScript, CAPTCHA, авторизацией или нестандартными API требуют отдельных адаптеров. Конкретные сайты ещё не проверены, поскольку адреса не заданы. В облаке доступ к выбранному сайту может потребовать добавления его домена в настройки сети.

## Шаблоны документов для Беларуси

Все документы формируются по выбираемому шаблону HTML, DOCX или XLSX. При первом запуске создаются редактируемые HTML-примеры поступления, счёта и расходной накладной в `templates/`. Они **не являются утверждёнными бланками ТН-2/ТТН-1**. Подключите свои согласованные формы с нужными обязательными реквизитами. Специальных транспортных полей и автоматической проверки полноты официальной ТТН в этой версии нет.

Общие теги:

`{{title}}`, `{{number}}`, `{{date}}`, `{{reference}}`, `{{seller}}`, `{{seller_details}}`, `{{customer}}`, `{{customer_details}}`, `{{currency}}`, `{{subtotal}}`, `{{tax_total}}`, `{{total}}`.

Теги строки товара:

`{{item.index}}`, `{{item.sku}}`, `{{item.name}}`, `{{item.unit}}`, `{{item.quantity}}`, `{{item.price}}`, `{{item.tax_rate}}`, `{{item.tax}}`, `{{item.amount}}`, `{{item.total}}`.

В HTML окружите повторяющуюся строку блоком `{{#items}}…{{/items}}`. В DOCX разместите теги товаров в строке таблицы: она повторяется на каждый товар. В XLSX используйте одну строку с тегами товаров на листе; ниже неё можно разместить итог. Для XLSX сложные формулы, объединения и ссылки после вставки строк требуют проверки шаблона. В Word заменяются теги в обычных абзацах, таблицах, абзацах колонтитулов; вложенные таблицы и текстовые блоки не поддерживаются.

Шаблон не перезаписывается. Неизвестный тег вызывает ошибку. HTML экранирует пользовательский текст, XLSX сохраняет подставленные значения, начинающиеся с `=`, как текст. При формировании через интерфейс копии использованных шаблонов и готовых документов сохраняются в папке данных и включаются в бекап. HTML можно открыть и распечатать через браузер; отдельной генерации PDF в этой версии нет.

## Резервные копии

Автоматическая ZIP-копия — при запуске, раз в час и при закрытии. «Создать копию» доступно в любой момент. Копия содержит согласованный SQLite-снимок базы, шаблоны, сформированные документы, прикреплённые исходные накладные и журнал обновления сайтов. Для каждого файла записана SHA-256 в манифесте. Пароли сайтов не используются и не сохраняются.

Восстановление всегда выполняется в **новую, ещё не существующую папку**: проверяются состав архива, безопасные пути, контрольные суммы, SQLite integrity_check и связи. Рабочая база не подменяется. После восстановления запустите приложение с `--data-dir` восстановленной папки.

Копии хранятся без автоматического удаления и не зашифрованы. Переносите их на другой диск/носитель и следите за свободным местом: копия на том же диске не защищает от поломки диска. Непрерывного резервирования и обновления цен при закрытой программе нет.

## Проверки

```bash
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/workspace/.cache .venv/bin/python -m pytest tests/test_shop.py -q
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/workspace/.cache .venv/bin/python tests/smoke_shop.py
```

Проверяются складские транзакции, недостаток товара, отмена, точность чисел и НДС, снимки цен, импорт прайсов, чтение HTML/JSON-LD и обход категорий с тестовым HTTP-клиентом, шаблоны трёх форматов, защита Excel-формул, восстановление, повреждённые архивы и выход за пределы папки. GUI-проверка проходит шесть разделов, создаёт счёт через диалог, проводит поступление и отгрузку, формирует документ и проверяет автоматическую копию.
