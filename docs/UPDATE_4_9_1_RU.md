# ПТО 4.9.1 — исправления пунктов 1–9 аудита

## Что изменилось

1. Команды SAVEPOINT, RELEASE и ROLLBACK TO разрешены только владельцу уже открытой
   серверной транзакции. Наблюдателю они запрещены. Вложенные транзакции сотрудника
   продолжают работать; чужая команда не заставляет ждать истечения транзакции.
2. После потери ответа на запись клиент не повторяет её автоматически. Сообщение
   сообщает, что сервер мог выполнить действие: после восстановления связи сначала
   проверьте результат. Повтор чтения и повтор подключения до отправки сохранены.
   Это предотвращает двойную запись; гарантировать результат потерянного COMMIT без
   проверки данных программа пока не может.
3. Отключение/удаление пользователя, изменение роли/ограничений и смена пароля
   отзывают сеансы и сохранённые входы. Незавершённая транзакция сеанса откатывается.
   Версия прав хранится в users.db и проверяется при запросах, в том числе если
   учётную запись изменило другое подключение к users.db.
4. Копия учитывает поля file_path, tu_path, custom_contract_path, doc_path и папки
   folder, folder_path, project_folder, contract_folder во всех обычных таблицах.
   Включены внешние папки всех разделов договоров, документы с составным ключом,
   накладные и документы сварочного модуля. Старое исключение сварочных файлов из
   копий больше не действует. Отсутствующие источники перечисляются в manifest.json.
   После восстановления упакованные пути переводятся в новую папку; подсказки
   folder_root_* сбрасываются, чтобы новые договоры не создавались в старом месте.
   Манифест содержит хэши файлов в архиве до переноса путей в восстановленной базе.
5. Обе базы снимаются под общей блокировкой только между транзакциями. Если
   транзакция открыта, резервирование быстро возвращает ошибку и не удерживает
   блокировку в sqlite3.backup. Почасовая служба повторяет попытку на следующей
   минутной проверке. Ожидание локальной блокировки ограничено 5 секундами,
   копирование SQLite — 120 секундами. Прежний готовый архив при ошибке сохраняется.
6. Сервер проверяет SQL также через SQLite authorizer. Разрешены только безопасные
   PRAGMA чтения; варианты записи с '=' и со скобками запрещены. Настройки интерфейса
   хранятся отдельно для каждого сетевого пользователя в users.db, общие настройки
   меняет администратор. Внешний вид, столбцы, фильтры, календарь, параметры шрифта
   экспорта и калькулятора остаются доступны сотрудникам/наблюдателям. Перечень —
   smetagaz/net_permissions.py. Старые общие значения служат значениями по умолчанию.
7. Прямая запись в audit_log и audit_ctx по сети запрещена, включая администратора.
   Доверенные триггеры продолжают вести журнал. Корзина восстанавливает записи через
   отдельную серверную операцию с проверкой роли и ограничений разделов; разрешено
   только служебное изменение признака restored в ходе восстановления.
8. Сводка и история оплат больше ничего не записывают при чтении. Старый начальный
   остаток рассчитывается без записи; его согласование выполняется при добавлении
   оплаты/смене связи. Наблюдатель видит реальные оплаты и может экспортировать
   реестр. Ошибка получения оплат больше не превращается в ноль: экспорт прерывается,
   сохраняя прежний файл.
9. Причина служебного снимка: 1–40 строчных латинских букв, цифр и '_', первый символ —
   буква. Пути, маски и разделители запрещены. Хранение: целое число от 1 до 100.
   Символическая ссылка вместо каталога backups не принимается; очистка не удаляет
   посторонние файлы/каталоги.

## Обновление

1. Сохраните независимую копию папки данных и внешних документов. Копия старой версии
   могла пропустить внешние папки договоров: одного старого ZIP для их защиты мало.
2. Закройте все клиенты и остановите сервер. Распакуйте новую программу отдельно,
   сохранив прежнюю папку программы для возможного возврата.
3. Обновите сервер и все клиенты. Сетевой протокол изменён с 1 на 2; смешанный запуск
   версий 4.9.0 и 4.9.1 не поддерживается. Учётные записи сохраняются; пользователю,
   права которого изменили, потребуется повторный вход.
4. Запустите сервер, затем клиенты. Создайте полную копию и проверьте восстановление
   в новую папку. Проверьте manifest.json: отсутствие исходного документа нельзя
   исправить резервированием.

Исходные рабочие SQLite-базы по-прежнему не зашифрованы. Файлы архивов ZIP не
зашифрованы; для защищённых внешних копий используется существующий формат SGB.
Административные сеансы и настройки в users.db не включаются в обычную клиентскую
копию данных, как и ранее: серверную конфигурацию сохраняют отдельно.

## Проверки

Новые регрессионные сценарии находятся в tests/test_security_491.py. Они проверяют
настоящий HTTPS, вложенные транзакции, отзыв доступа с откатом, запреты PRAGMA и
служебных таблиц, раздельные настройки, чтение оплат, сохранность старого экспорта,
ограничение ожидания снимка, перенос внешних документов и потерю сетевого ответа.

Команда: `python -m pytest tests -q` (дополнительно нужен pytest).
Сборка Windows остаётся через `build_windows.bat server`.
Проверки этой правки проводились на Python 3.12 / Linux / Qt offscreen,
с PyQt6 и Qt 6.11.0; готовая Windows EXE в этом архиве не поставляется.

В эти девять исправлений не входят замена модели прямого SQL полноценным предметным
API, оптимизация всех сетевых запросов, обновление сторонних зависимостей и
унификация фоновых заданий консольного и оконного сервера.
